# Módulo 9: Proyectos Integradores

Los ocho módulos anteriores te dieron las piezas, una por una, con mucho andamiaje: un
dataset preparado por el libro, ejercicios acotados a un solo concepto, código de ejemplo casi
listo para copiar. Este módulo final invierte esa relación: **tú eliges el dataset, tú decides
qué técnicas aplicar, y el libro te da la estructura del proyecto, no el código.**

## Cómo están organizados estos capítulos

A diferencia de los Módulos 1-8, estos cinco capítulos no enseñan conceptos nuevos de pandas
— son **briefs de proyecto**: un objetivo, un dataset sugerido, fases con checklist, y una
rúbrica de autoevaluación. El código que incluyen es *scaffolding* (estructura de arranque),
no una solución completa. Completar cada proyecto requiere que vuelvas, según necesites, a los
capítulos correspondientes de módulos anteriores.

## Los cinco proyectos

- **[9.1 Proyecto 1: EDA Completo](01-eda-completo.md)** — un análisis exploratorio de
  principio a fin sobre un dataset público real. Aplica principalmente los Módulos 2-4.
- **[9.2 Proyecto 2: Time Series](02-time-series.md)** — análisis de tendencias,
  estacionalidad y forecasting básico sobre datos temporales. Aplica principalmente el
  Módulo 5.
- **[9.3 Proyecto 3: ETL e Integración](03-etl-integracion.md)** — un pipeline que combina
  múltiples fuentes de datos y las carga a una base de datos, con automatización. Aplica
  principalmente los Módulos 2, 3, 5 y 8.4.
- **[9.4 Proyecto 4: ML End-to-End](04-ml-end-to-end.md)** — un problema de predicción
  completo, desde feature engineering hasta evaluación de un modelo. Aplica principalmente el
  Módulo 6.
- **[9.5 Proyecto 5: Capstone Personal](05-capstone.md)** — un proyecto de tu elección total,
  usando cualquier combinación de técnicas del libro, pensado explícitamente como pieza de
  portafolio profesional.

## Cómo elegir un dataset

Cada proyecto sugiere fuentes de datos públicas apropiadas para su tipo de análisis
(principalmente [Kaggle Datasets](https://www.kaggle.com/datasets) y el
[UCI Machine Learning Repository](https://archive.ics.uci.edu/)), pero la elección específica
del dataset es tuya. Un buen dataset para estos proyectos:

- Tiene al menos varios cientos de filas (idealmente miles) y múltiples columnas de tipos
  variados (numéricas, categóricas, al menos una de fecha si aplica).
- Te interesa genuinamente — vas a pasar varias horas explorándolo, y eso es mucho más
  llevadero con un tema que te importe.
- No es un dataset "de juguete" ya perfectamente limpio (como el clásico Iris) — parte del
  valor pedagógico de estos proyectos es enfrentar datos con problemas reales de calidad.

## Cómo usar la rúbrica de cada proyecto

Cada capítulo cierra con una rúbrica de autoevaluación en formato checklist. No es un examen —
es una guía de lo que un análisis o pipeline "completo" en ese dominio típicamente incluye.
Úsala antes de dar un proyecto por terminado, y también como guía de qué mostrar si conviertes
el proyecto en una pieza de portafolio (tema central del Proyecto 5).
